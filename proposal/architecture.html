Meridian Components — Inventory Dashboard

Current-state architecture review. Produced during engagement onboarding as a deliverable for Meridian IT. Based on direct codebase inspection of the system delivered by the previous vendor (Nov 2024).

Data Flow

1 · User action
FilterBar.vue
User selects warehouse, category, period, or status. Updates shared singleton state.
→
2 · State
useFilters.js
Singleton composable. Holds refs for all 4 filter values. getCurrentFilters() returns param map.
→
3 · HTTP
api.js
18 Axios methods. Builds URLSearchParams from filter map. Calls backend at localhost:8001.
→
4 · Backend
FastAPI
Receives query params. Applies apply_filters() to in-memory data. Returns Pydantic model.
→
5 · Data
JSON → Memory
7 JSON files loaded at startup into Python lists. No DB queries. All filtering is in-memory.

Views watch filter state with watch() and re-call the API when filters change. Derived data lives in computed() properties — no redundant fetches.

Frontend Structure

Views (7)

Dashboard.vue
KPI summary, order health donut, inventory by category, shortages
Inventory.vue
Stock levels table, client-side search, detail modal, filter integration
Orders.vue
Order list with status/warehouse/category/month filters
Reports.vue
Quarterly performance, monthly trends, MoM analysis — defects
Spending.vue
Revenue vs costs, monthly spend, category breakdown, transactions
Demand.vue
Demand forecast trends (increasing / stable / decreasing)
Backlog.vue no route
Shortage tracking with priority levels. Exists but missing from router.

Composables (3 — shared state)

useFilters.js
Singleton. Refs: selectedPeriod, selectedLocation, selectedCategory, selectedStatus. Methods: resetFilters(), getCurrentFilters(), hasActiveFilters()
useAuth.js
Mock user session. Language-aware computed properties (name, title, tasks in EN/JA). getInitials(), logout()
useI18n.js
Custom i18n (not vue-i18n). setLocale(), t(), translateProductName(), translateWarehouse(). Fallback: ja → en. Currency auto-selects USD/JPY by locale.

Key Components

FilterBar.vue
Global filter controls. Writes to useFilters singleton. Present on all views.
LanguageSwitcher.vue
EN ↔ JA toggle. Calls useI18n.setLocale(). Persists to localStorage.

Recent transaction records
purchase_orders.json empty
File exists, schema defined, but contains empty array []

All data loaded into Python lists at server startup via mock_data.py. Filtering is performed in-memory. No database layer — appropriate for current scale, will need revisiting as data volume grows.

Known Technical Debt

  • !
    Reports module defects R1 — in scope
    Multiple filter wiring issues, i18n gaps, and display inconsistencies. Previous vendor acknowledged this was "in progress" at contract end. Full audit underway.
  • !
    6 missing API endpoints silent failures
    Tasks (4 endpoints) and Purchase Orders (2 endpoints) are called by the frontend but not implemented in FastAPI. Calls return 404 silently — users see no error, features simply don't work.
  • ~
    Backlog view not in router
    Backlog.vue is fully implemented but its route is missing from the Vue Router config. The view exists but is unreachable via normal navigation.
  • ~
    Reports and Backlog views not i18n-integrated D2 — in scope
    All other views use the i18n system. Reports.vue and Backlog.vue have hardcoded English strings — Tokyo warehouse staff see English on these views regardless of language setting.
  • ~
    No automated test coverage R3 — in scope
    No end-to-end or unit tests were delivered by the previous vendor. Meridian IT has blocked all changes as a result. Playwright suite is being established as part of this engagement.
  • ~
    CORS wildcard in production-bound code
    FastAPI is configured with allow_origins=["*"]. Acceptable for development; should be locked to known origins before any production deployment.
