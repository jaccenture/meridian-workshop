Our Approach

Stabilize → Test → Extend

The sequencing is deliberate. Fixing bugs without tests means they come back. We establish a clean, tested baseline before building anything new.

Phase 1–2

Stabilize

Full Reports audit. Resolve every defect. Pair each fix with a regression test. IT freeze lifted.

Phase 2

End-to-end Playwright suite covering all four primary views. Safe foundation for every change that follows.

Phase 3–4

Extend

Build Restocking on a system that works. Add UI polish, i18n, and dark mode without breaking what's already fixed.

No open items at contract end. No "in progress" in our handoff notes.

Required — R1

Reports Module Remediation

We will conduct our own full audit — not work from an incomplete list. Every defect found will be resolved and covered by a regression test.

What we'll audit

  • Every filter mapped against the API parameters it should send
  • Internationalization coverage in Reports specifically (known gap from handoff)
  • Options API remnants contributing to inconsistent behavior
  • Console errors, incorrect API calls, edge cases in data display
Deliverable

All defects resolved. Regression test for each fix. Zero open issues at phase close.

Required — R3

Automated Browser Testing

R3 is what unblocks everything else — including Meridian's ability to accept future changes after this engagement ends.

Tool

Playwright

Industry-standard browser automation. Integrates cleanly with Vue + FastAPI. Tests are readable and maintainable by Meridian IT without our involvement.

Scope

All four primary views

Dashboard, Inventory, Orders, and Reports. Happy-path flows including filter application and data verification. Sufficient for IT sign-off.

Outcome

IT team can run the suite independently. Future changes — by Meridian's own team or a future vendor — have a safety net that didn't exist before.

Required — R2

Restocking Recommendations

A new view that recommends purchase orders based on current stock, demand forecast, and an operator-supplied budget ceiling.

How it works

  • Pull stock levels per SKU and warehouse from existing inventory API
  • Pull demand forecast from existing demand API
  • Rank restock candidates by urgency (stock coverage vs. demand rate)
  • Apply operator's budget ceiling — include items in priority order until budget is reached
  • Surface as a recommended purchase order list: item, warehouse, quantity, estimated cost

Integrated, not bolted on. The Restocking view works with the existing warehouse filter. No new infrastructure — logic lives in the existing FastAPI layer.

Required — R4

Architecture Documentation

The previous vendor's handoff is two pages. Meridian IT cannot maintain a system they don't have a clear picture of. We deliver the document they should have received in 2024.

What we'll cover

  • Stack summary — Vue 3, FastAPI, JSON data layer, ports, tooling
  • Component map of frontend views and their relationships
  • Data flow: UI filters → API client → FastAPI → filtered response
  • Full API surface with parameters and response shapes
  • Known technical debt (incomplete migration, no database, i18n gaps)

Format: self-contained HTML with visual diagram. Opens in any browser. No tooling required for Meridian IT to read or share it.
